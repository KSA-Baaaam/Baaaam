# 글쓰기 수정 및 실제 검증

검증일: 2026-09-05

## 결과

이전 점검에서 재현된 10개 오류를 수정하고 자동 회귀 검사와 실제 브라우저 검증을 수행했다. 웹사이트는 재배포하지 않았다. DB 스키마와 권한 정책도 변경하지 않았다.

## 수정 사항

- 기기 초안 키를 사용자 ID와 글 ID로 분리했다. 소유자를 알 수 없는 기존 공용 초안은 삭제하지 않으며 다른 계정에 자동으로 복원하지 않는다.
- 공개된 글의 편집은 기기에만 임시저장하고 명시적인 발행에서만 공개본을 갱신한다. 서버의 임시저장 요청도 `status = draft` 조건을 적용한다. 공개 글의 수정 초안은 기기 간 동기화되지 않는다는 안내를 작성 화면에 표시했다.
- 초안 복구 선택 전에는 자동저장을 중지한다. 복구 창 바깥 클릭이나 Escape로 최신 초안이 폐기되지 않도록 명시적인 버전 선택을 요구한다.
- 입력 직후 동기식 복구 기록을 남겨 700ms 이내 이동·종료에도 최근 입력을 보존한다. IndexedDB 저장은 트랜잭션 완료 후 성공으로 판단하고 대체 저장 기록도 읽는다.
- IndexedDB 미지원 환경의 삭제와 발행 후 로컬 정리 실패를 분리했다. 서버 발행 성공 후 정리에 실패해도 발행 실패로 표시하지 않는다.
- 신규 발행 전에 생성 ID를 보존하여 후속 발행 요청 실패 시 같은 글을 재사용한다. 연속 클릭 중복 요청도 차단한다. 다만 최초 INSERT의 응답 자체가 유실되는 불확정 네트워크 상황까지 원자적 멱등성을 제공하는 변경은 아니다.
- 표의 열 너비와 병합 속성, 번호 목록의 시작 번호를 독자 화면에도 반영한다.
- 블록 검색 중 한글 조합 Enter와 keyCode 229를 실행 키로 처리하지 않는다.
- 대표 이미지 저장 실패 후 다시 시도할 수 있도록 디코딩 준비 상태와 일시적인 업로드 오류를 분리했다. 이미지 처리 중 중복 저장도 방지한다.
- 사진 업로드/편집 중 발행을 차단하고, 클라우드 저장 중 추가한 변경을 모두 저장한 것처럼 표시하지 않도록 수정했다.

## 자동 검사

실행: `npm run test:editor` (Node 22.15 이상), `npm run validate`, `npm run build`.

- 서식 적용/해제, 선택 영역 유지, 기본/선택 메뉴, JSON 저장과 독자 렌더링
- 목록·번호·체크·인용·코드, 표 삽입 및 행/열 추가·삭제
- 표 너비/병합과 목록 시작 번호, 이미지 크기/캡션 보존
- 한글 조합 Enter, 태그 중복 방지와 10개 제한
- 즉시 화면 이동 시 초안 유지, 저장소 대체 경로
- 계정 간 초안 분리, 복구 선택 전 보존
- 공개 글 임시저장 보호, 발행 실패 재시도 및 연속 클릭 방지
- 발행 후 정리 실패 시 정상 화면 이동, 이미지 업로드 실패 재시도

총 26개 PASS 항목. 타입·린트·빌드 통과. 빌드에는 기존 렌더러 청크 500kB 초과 경고가 남아 있다. 운영 의존성의 `npm audit --omit=dev` 결과는 취약점 0개이며, 전체 개발 도구 의존성에는 기존 취약점 경고가 있으므로 별도 유지보수가 필요하다.

## 실제 브라우저 → Supabase → 비로그인 독자 확인

로컬 최신 코드에서 기존 작성자 세션으로 실행했다. 기존 사용자의 글은 수정하지 않았다.

1. 검증용 글(ID 15)에 제목·수학 카테고리·한국어 본문을 입력했다.
2. 본문 일부를 선택하여 기울임·밑줄·취소선·강조를 클릭했다.
3. 실제 Supabase 임시저장 후 `/write/15`로 이동했고, 새로고침 뒤 같은 부분을 선택했을 때 네 가지 서식이 모두 활성화됐다.
4. 발행 후 독립된 비로그인 브라우저에서 제목과 `<mark><u><s><em>…</em></s></u></mark>` 출력을 확인했다.
5. 공개 글의 제목을 바꾸고 임시저장한 뒤 비로그인 브라우저를 새로고침했다. 공개 제목은 원래 내용 그대로였다.
6. 사이트의 기존 마스코트 파일로 대표 이미지 자르기/업로드를 수행했다. 수정본 발행 후 홈 카드에서 Supabase 이미지가 1600×700으로 정상 로드됐다.
7. 375×812 화면에서 문서 너비 375px, 본문 335px, 기울임 계산 스타일 `italic`을 확인했다. 해당 읽기 화면은 가로 넘침이 없었다.
8. 실제 작성·발행 탭의 error/warn 로그는 없었다.

검증용 글 ID 15와 대표 이미지의 영구 삭제는 사용자 확인을 요청한 상태다. 웹사이트 재배포는 수행하지 않았다.

## 한계

- 한글 조합 관련 회귀 검사는 조합 이벤트를 합성했다. 실제 모든 iOS/Android 한글 키보드와 브라우저 조합을 확인한 것은 아니다.
- Supabase 관리용 SQL 연결은 권한 오류가 발생했다. 실제 저장·업로드·발행은 정상 작성자 세션과 독립된 비로그인 읽기 경로로 확인했다. 운영 RLS 전체에 대한 보안 감사는 수행하지 못했다.
- 위 테스트는 확인된 재현 사례에 대한 검증이며 모든 가능한 오류가 없다는 보증은 아니다.
