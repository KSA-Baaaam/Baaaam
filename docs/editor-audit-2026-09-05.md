# 글쓰기 기능 점검 결과

> 후속 수정과 실제 검증을 완료했다. 현재 결과는 [검증 보고서](editor-verification-2026-09-05.md)를 참고한다. 아래는 수정 전 재현 기록이며, 코드 위치도 당시 기준이다.

점검일: 2026-09-05 · 기준 커밋: `8496f1094cdee1cf35838a15a51be199edf746a6`

현재 코드에서 오류 10개를 재현했다. 아래 결과는 제품 수정 전 점검 기록이다. 제품 코드, 운영 데이터와 배포는 변경하지 않았다.

## 점검 방법과 범위

- 실제 React 편집기와 글 작성 페이지를 격리된 JSDOM 환경에 마운트했다. 입력, 클릭, 선택, 한글 조합 키 이벤트와 화면 해제를 실행했다.
- 실제 저장 서비스에 테스트 응답을 연결해 저장 요청과 실패 후 재시도를 검사했다. 운영 DB에 테스트 글을 발행하지 않았다.
- 편집 JSON을 실제 미리보기/독자용 렌더러에 전달해 출력 보존 여부를 검사했다.
- TypeScript 및 ESLint 검사 통과.
- 운영 Supabase 정책 조회는 연결 계정의 권한 오류로 실패했다. 저장소에 있는 RLS 정책을 검토했지만 운영 DB에 동일하게 반영됐는지는 확인하지 못했다.
- 실제 iOS/Android 키보드·터치·사진 디코딩, 실제 네트워크를 통한 파일 업로드/발행, 모든 브라우저의 시각적 배치는 이번 재현 테스트에 포함되지 않는다. 오류가 더 없다는 보증은 아니다.

## 확인된 오류

### 1. [P1] 임시글이 계정별로 분리되지 않음

- 위치: `src/pages/WritePost.tsx:112`, `src/pages/WritePost.tsx:128`, `src/services/draftStorage.ts:38`.
- 재현: A 작성자의 새 글 초안을 공용 `new` 키에 저장한 뒤 B 작성자로 글 작성 페이지를 열었다. A의 제목이 B의 입력창에 표시됐다.
- 영향: 같은 브라우저를 공유하는 계정 사이에 비공개 초안이 노출되고, 다른 작성자 이름으로 이어서 저장될 수 있다. 서버 권한 우회가 아니라 브라우저 임시 저장소의 계정 분리 문제다.
- 수정 방향: 사용자 ID와 글 ID를 함께 저장 키로 사용하고 계정 변경 시 편집 상태를 초기화한다. 기존 공용 초안의 소유자를 확인할 수 없다면 새 사용자에게 자동 복원하지 않는다.

### 2. [P1] 발행된 글의 임시저장이 공개 본문을 변경함

- 위치: `src/pages/WritePost.tsx:191`, `src/services/posts.ts:210`.
- 재현: `updateDraft`에 변경 본문을 전달하면 기존 `posts` 행의 `content`를 직접 갱신하며 `status`는 바꾸지 않는다. 기존 행이 `published`이면 공개 상태를 유지한다. 작성 페이지는 수동 임시저장과 2분 주기 자동저장에서 이 함수를 호출한다.
- 영향: 발행 버튼을 다시 누르기 전에 수정 중인 내용이 독자에게 공개된다. 요청 형태와 코드로 확인했으며 운영 글을 실제 수정하는 테스트는 하지 않았다.
- 수정 방향: 공개본과 수정 초안을 분리하고 명시적인 발행 작업에서만 공개본을 갱신한다.

### 3. [P1] 복구를 선택하기 전에 최신 로컬 초안이 덮어써짐

- 위치: `src/pages/WritePost.tsx:113`, `src/pages/WritePost.tsx:145`.
- 재현: 서버보다 최신인 로컬 초안으로 수정 페이지에 들어가 복구 창을 띄운 뒤 700ms 이상 기다렸다. 선택하기 전인데도 저장소의 제목이 서버 원본으로 바뀌었다.
- 영향: 복구 창이 열린 상태에서는 메모리에 복구본이 남아 있으나, 새로고침하거나 페이지를 떠나면 최신 초안을 잃을 수 있다.
- 수정 방향: 복구 충돌을 해결할 때까지 로컬/클라우드 자동저장을 멈추고 선택한 버전만 저장한다.

### 4. [P1] 입력 직후 페이지를 떠나면 마지막 변경이 저장되지 않음

- 위치: `src/hooks/useLocalDraft.ts:14`.
- 재현: 초안 변경 후 700ms 저장 지연이 끝나기 전에 컴포넌트를 해제했다. 이후 저장소에 해당 변경이 없었다.
- 영향: 작성 화면의 뒤로가기나 사이트 내부 링크를 곧바로 누르면 마지막 입력이 사라진다. 내부 화면 이동에서는 탭 숨김 이벤트도 발생하지 않는다.
- 수정 방향: 페이지 이탈 시 최신 초안을 확정 저장한다. 성공적인 발행 후 삭제한 임시글을 이탈 처리로 다시 생성하지 않도록 구분해야 한다.

### 5. [P2] IndexedDB를 사용할 수 없으면 발행 후 임시글 정리가 실패함

- 위치: `src/services/draftStorage.ts:63`, `src/pages/WritePost.tsx:266`.
- 재현: IndexedDB가 없는 환경에서는 `save`가 localStorage로 성공하지만, `remove`는 localStorage를 지우고도 IndexedDB 오류를 그대로 반환한다.
- 영향: 서버 발행이 성공했더라도 뒤따르는 임시글 정리 실패가 발행 실패처럼 표시되고 글 화면으로 이동하지 않을 수 있다.
- 수정 방향: 대체 저장소만 사용한 경우의 삭제를 정상 처리하고, 서버 발행 성공과 로컬 정리 오류를 분리한다.

### 6. [P2] 신규 글 발행이 중간 실패하면 재시도 때 초안이 중복 생성됨

- 위치: `src/services/posts.ts:224`.
- 재현: 새 초안 INSERT는 성공하고 다음 발행 UPDATE만 실패하도록 응답을 구성했다. 동일한 신규 글을 두 번 발행 시도하자 INSERT가 두 번 호출됐다.
- 영향: 첫 요청의 글 ID가 화면에 반환되지 않아 재시도마다 새로운 초안이 생긴다.
- 수정 방향: 생성 ID를 먼저 보존해 동일한 행을 재사용하거나, 신규 발행을 원자적·중복 방지 가능한 서버 작업으로 만든다.

### 7. [P2] 표의 열 너비 및 병합 정보가 미리보기·발행 화면에서 사라짐

- 위치: `src/components/post/PostContentRenderer.tsx:158`.
- 재현: `colwidth`, `colspan`, `rowspan` 속성을 가진 실제 표 JSON을 렌더링했다. 출력 셀과 표에는 해당 속성이 반영되지 않았다.
- 영향: 편집기에서 조절한 열 너비가 공개 글에 적용되지 않는다. 붙여넣기 등으로 들어온 병합 셀은 배치가 달라질 수 있다.
- 수정 방향: 표 너비와 셀 속성을 독자용 렌더러에도 반영한다.

### 8. [P2] 블록 검색에서 한글 조합 확정 Enter가 명령을 실행함

- 위치: `src/components/editor/EditorBlockMenu.tsx:97`.
- 재현: 검색창에 `isComposing: true`, 키 코드 229인 Enter 이벤트를 전달했다. 조합 확정만 해야 하는데 첫 블록 명령이 실행되고 메뉴가 닫혔다.
- 영향: 한글로 블록 이름을 찾는 중 엉뚱한 블록이 들어갈 수 있다.
- 수정 방향: 조합 중 이벤트를 무시하고, 조합 종료 후 일반 Enter에서만 실행한다.

### 9. [P2] 대표 이미지 저장 실패 후 같은 창에서 재시도 불가

- 위치: `src/components/editor/CoverImageCropDialog.tsx:193`, `src/components/editor/CoverImageCropDialog.tsx:284`.
- 재현: 이미지 처리 성공 후 업로드 콜백이 일시 오류를 반환하게 했다. 오류 문구가 설정되면서 저장 버튼이 비활성화됐다. 선택 영역 초기화를 눌러도 비활성 상태가 유지됐다.
- 영향: 연결이 회복되어도 사용자가 창을 닫고 사진을 다시 골라야 한다.
- 수정 방향: 복구 가능한 저장 실패는 재시도를 허용하고, 잘못된 이미지처럼 진행 불가능한 오류와 구분한다.

### 10. [P2] 번호 목록의 시작 번호가 보존되지 않음

- 위치: `src/components/post/PostContentRenderer.tsx:150`.
- 재현: 시작 번호가 5인 번호 목록을 렌더링했으나 출력 `<ol>`에 `start`가 없었다.
- 영향: 이어지는 번호 목록이나 붙여넣은 목록이 미리보기·발행에서 1부터 다시 시작한다.
- 수정 방향: 유효한 `start` 속성을 출력에 전달한다.
